# X1hub

- 網站：<https://www.x1hub.com/>
- 語言：`all`。網站介面主要為英文，影片標題包含中文、日文及英文；不保證影片有字幕。
- 成人來源：`isNsfw = true`。目前版本為 `16.5`，套件 ID 為 `eu.kanade.tachiyomi.animeextension.all.x1hub`。
- 相容目標：AniZen 0.5.220；沿用本倉庫 v16 來源介面及宿主提供的依賴。

2026-11-14 狀態：16.5 的[正式 CI／簽名／套件庫發布](https://github.com/Supebuff/sb-extensions-source/actions/runs/43598796954)已成功，目前仍待此版本的手機列表、圖片與播放回報。完整已確認及待確認項目見[專案現況](../../../docs/CURRENT_STATUS.md)。

## 功能與設定

- 熱門：網站的 Most Viewed；最新：Latest。
- 關鍵字搜尋、一般列表分頁，以及搜尋／分類的 AJAX 分頁。
- 搜尋無結果時回傳空列表，不混入網站另外顯示的推薦影片。
- 常用分類：中文、日本、亞洲、素人、Cosplay、動畫、Webcam、ASMR。搜尋文字留空時才套用分類；有文字時以關鍵字搜尋為準。
- 縮圖、影片詳情、分類／標籤；每部影片呈現為一集「完整影片」。
- 解析頁面 `flashvars` 內的公開 MP4 連結，支援 KVS `function/0` 雜湊排列還原，依畫質由高到低排列。排除登入跳轉，沒有公開畫質時明確報錯。
- 每次開播重新請求影片頁，不持久保存有時效的播放連結。傳給 App 的影片標頭包含該影片頁的 Referer。
- 16.2 起，選定畫質時先經宿主 HTTP 流程解析 `/get_file/` 重新導向，以 `Range: bytes=0-11` 檢查 MP4 開頭，再交付最終媒體網址。播放器後續可直接請求 CDN，減少拖曳、重連及切網路時重新經過網站驗證入口的機會；不把探測用的 Range 帶入播放／下載標頭，也不把網站 Cookie 或授權標頭轉交不同主機。
- 16.3 起，從影片頁、入口重新導向到播放器交接，都保留宿主實際送出的 User-Agent；播放器另外取得最終媒體主機成功請求中使用的 Cookie，避免驗證後的標頭在轉接時遺失。僅複製這兩類必要標頭，不轉交探測 Range 或 Host，也不把網站 Cookie／授權送給其他主機。
- 來源設定顯示「功能列表」、「同一主機請求間隔」及使用提示。預設 0.5 秒，另可選擇 1 秒或 2 秒。
- 16.4 新增選用的 Scrapling 外部服務。填入服務位址與專用金鑰後，列表／詳情、整批縮圖及 MP4 影片都經同一台電腦的網關；留空使用原有直連。位址或金鑰錯誤會明確報錯，不會默默改用手機直連。
- 16.5 起，頁面及資源票證請求遇到可辨識的 TCP 連線失敗、重設或過早關閉時，等待 350 毫秒後以新連線額外嘗試一次。慢速讀取、TLS／權限／DNS 錯誤及取消操作不進入此恢復流程，收到 HTTP 回應也不由此流程重試。持續失敗會顯示分類代碼，例如 `CONNECT_FAILED`、`CONNECTION_RESET`、`TIMEOUT`，方便區分原因；訊息不包含原始例外中的網址或金鑰。

頁面請求按主機分別節流，重新導向的目的地主機也適用。HTTP 429 以及含 `Retry-After` 的 HTTP 503 會進入冷卻，支援秒數與 HTTP 日期；缺少有效等待時間的 429 由 30 秒逐次延長，預設退避上限 15 分鐘，網站指定的較長等待時間仍會保留。冷卻期間回報剩餘時間，不自動重試 HTTP 錯誤。一般間隔等待與進行中的 HTTP 呼叫可隨協程取消。

直連模式的縮圖由 App 直接載入，本來源沒有加入手機縮圖快取；頁面 Cookie 沿用宿主管理，媒體交接僅使用最終媒體主機已成功使用的 Cookie。網關模式在服務端保留獨立瀏覽器會話與縮圖快取，原站 Cookie 不傳到手機；服務金鑰也不放入圖片／影片網址。圖片與媒體以各資源的簽章連結載入。網關以 0.5 秒間隔處理網站請求及冷卻，原有間隔設定只控制手機直連。

影片緩衝、下載、續播、投放及外部播放器仍由 App 控制。網關支援 MP4 的 Range／HEAD／取消，但電腦必須在線、手機或外部接收器必須能連到網關；行動數據需另設私人 VPN／隧道。影片票證 12 小時、圖片票證 7 天，到期或來源媒體 URL 失效時請重新開播／整理列表。切換服務設定後重新整理列表及詳情，已儲存縮圖不會立即重寫。設定及操作方式見 [網關說明](../../../services/challenge-gateway/README.md)。

不支援相簿、帳號管理、上傳、網站收藏／播放清單，以及付費或登入限定畫質。網站顯示的 1080p 若實際導向登入頁，不會列為可播放選項。網站存取限制與連結到期仍可能使播放失敗；此時重新開啟影片以取得新連結。

## 開發驗證

離線測試使用中性的合成 HTML，涵蓋一般及 AJAX 分頁、特殊字元、懶載入縮圖、格式變更與空結果的區分、KVS 固定測試向量、登入／廣告跳轉排除、畫質排序、限流冷卻、重新導向與協程取消。測試位於 `test/`，避免被 `common.gradle` 的正式 `src/` 來源集打包。

```sh
./gradlew :src:all:x1hub:testDebugUnitTest :core:testDebugUnitTest
./gradlew :src:all:x1hub:assembleRelease -PunsignedRelease=true
python -m unittest discover -s .github/tests -v
```

另有手動啟用的網站煙霧測試，正常 CI 會略過，不依賴即時網站。它以少量請求檢查熱門、最新、搜尋、分類的前兩頁，以及無搜尋結果、詳情、縮圖和最多兩個公開畫質。每個畫質先驗證最終媒體網址與 MP4 開頭，再獨立請求該網址的前 1024 bytes；不下載完整影片，也不輸出標題或帶權杖的媒體網址。

```sh
X1HUB_LIVE_TEST=1 ./gradlew :src:all:x1hub:testDebugUnitTest --tests '*.LiveSiteTest'
```

PowerShell 使用 `$env:X1HUB_LIVE_TEST='1'` 後執行對應 `gradlew.bat` 命令；結束後移除該環境變數。Gradle 將這個開關視為測試輸入，切換開關會重新執行測試。

需要重現特定影片時，可同時指定 `X1HUB_LIVE_VIDEO_URL` 為本站 `/videos/` 影片頁網址；未指定時從最新列表取樣。這個參數也列為 Gradle 測試輸入；測試不輸出完整影片或媒體網址。

網站格式參考為本站 KVS 5.5.1 播放器的公開設定；雜湊排列另以 [yt-dlp 的 KVS 解析](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/generic.py)交叉核對。測試不執行網站 JavaScript。

2026-11-05 的少量實站樣本中，熱門、最新、搜尋及中文分類的前兩頁各有 24 筆且內容不同；無搜尋結果未混入推薦影片。單一影片的 720p／480p 均回傳 HTTP 206，前 1024 bytes 通過 MP4 `ftyp` 檢查，縮圖回傳 HTTP 200 圖片。這些 HTTP 結果僅代表當時樣本，不代表完整片庫或長時間播放；後續手機回報另見下節。

CI 會自動辨識此新增模組，執行 JVM 測試、Release 建置、固定金鑰簽名與憑證驗證。安裝請使用 CI 的 `signed-apks-*`，操作方式見 [CI 文件](../../../docs/CI.md)。

## 手機實測與已知狀況

2026-11-05 使用者回報：AniZen 0.5.220、Android 16、X1hub 16.1。以下是少量影片的實際操作結果，不代表全片庫與所有網路環境。

- 列表：首次遇到 Cloudflare 自動驗證失敗；在 WebView 開啟並完成驗證後，返回重試可正常載入。目前保留此手動流程，自動驗證失敗原因未定。
- 開播、畫質切換、拖曳、續播及外部播放器：使用者回報功能可用。
- 畫質切換／拖曳等待時間：使用者反映轉圈較久，已確認沒有同時下載；決定先繼續觀察，原因尚未確定，未修改播放器或來源參數。
- 下載：曾於 100% 的收尾階段出現 `Downloader.finalizeDownload` 的 `Operation not permitted` 與 `Could not create destination file`；在「其他 → 設定 → 資料與儲存空間 → 儲存位置」透過系統選擇器重新授權原 AniZen 資料夾後，使用者確認正常完成。此案例未修改插件解析或刪除原資料。
- 網路切換（2026-11-06 補充）：使用者確認由行動數據切換至 Wi-Fi 後播放失敗，需在 WebView 完成網站驗證才恢復。此樣本顯示切網路後可能需要重新驗證；尚未確認是何項驗證狀態改變，也未證實媒體網址綁定 IP。恢復方式為先穩定使用新網路，在 WebView 完成驗證，再返回重新開播；不需要重新授權儲存位置。
- 仍待逐項確認：成人篩選、縮圖與設定頁、搜尋／分類操作、持續捲動分頁、長時間播放、重啟後的驗證狀態、其他網路切換方向與自動恢復、連結到期後重新解析、背景播放及投放。

若 Cloudflare 反覆要求驗證，或 WebView 成功後返回仍失敗，需重新調查宿主／網站的驗證與 Cookie 流程。下載若再次失敗，先根據日誌區分媒體請求失敗與儲存收尾失敗，不把進度 100% 視為已完成下載。

16.2 的最終媒體網址解析針對上述 16.1 切網路案例改善請求路徑，尚待手機驗證：行動數據與 Wi-Fi 雙向切換後的續播、切換後拖曳／換畫質、長時間播放與連結到期，以及下載／外部播放器相容性。它不保證網站入口能自動通過互動驗證，也不控制 MPV 的網路重連；若 CDN 本身要求重新驗證或網址已失效，仍可能需要重新開播或進 WebView。列表與縮圖的 Cloudflare 驗證不因此自動解決。

2026-11-06 後續回報：使用者確認已更新至 16.2 並重新開播，但影片 53587 在尚未切網路時就無法開播；AniZen 內建播放器日誌有 MP4 索引矛盾與 TLS 讀取失敗，外部播放器持續轉圈，WebView 網站播放器另有閃退回報。使用者進一步確認，同片在獨立瀏覽器使用 Wi-Fi 或行動數據均可播放，AniZen 仍失敗。開發端少量 HTTP／MP4 索引檢查未重現同一索引矛盾，不能據此認定手機端正常或影片完整無損。

16.3 修正可由測試重現的網路層標頭遺失，並以影片 53587 通過 720p／480p 的實站解析與位元組範圍檢查；尚未確認這就是手機起播故障的唯一原因。請先重測同片在內建及外部播放器的開播，再測網路切換、拖曳、切畫質、下載與長時間／連結到期後的恢復。WebView 宿主閃退沒有在本套件修改，不將其列為已修復。

開發差異、技術細節與踩坑紀錄見 [插件技術與踩坑紀錄](../../../docs/EXTENSION_NOTES.md)。

2026-11-14 已依使用者選擇實作 Scrapling 網關與 X1hub 試點，部署目標為目前 Windows 電腦。開發端透過網關取得列表、24 張縮圖，以及影片起始／位移後各 1024 bytes 的有效 MP4 範圍。尚未建立本站真實 Cloudflare 挑戰自動解開的證據，也未驗證 16.4 在手機上的起播、切網路、長時間播放、下載及外部播放器；不將先前 16.1 的裝置結果視為 16.4 已通過。原始方案比較見 [評估紀錄](../../../docs/X1HUB_CLOUDFLARE_OPTIONS.md)。

同日 16.4 手機補充：列表曾顯示「無法連線網關」，重新刷新後恢復；手機瀏覽器存取 `/healthz` 可取得 `status: ok`，設定的服務位址亦正確。20:54 的日誌包含 6 筆網關圖片磁碟快取成功及其後 6 筆記憶體快取成功，沒有保留先前連線失敗的例外，也沒有播放器紀錄，不能據此確定根因或宣稱播放通過。16.5 的單次恢復與錯誤分類針對此可恢復症狀改善用戶端；仍待手機重新測試列表、縮圖與播放，未認定失效的重用連線就是此次原因。
